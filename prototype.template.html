Is SignalCore a good idea?

Short answer: yes as an interview piece, and plausibly as a product, if it sells the skeptic rather than the clustering. Below are the scorecard, the design fixes this prototype already applies, and the risks.

Verdict

The problem is real and universal: roadmaps get bent by the loudest account, and churn signals hide in telemetry nobody reads next to the tickets. The concept’s best idea is not ingesting feedback (many tools do that) but cross-examining it: refusing to believe a theme until behaviour and revenue agree, and saying so out loud when they don’t.

As an interview artifact for a product leader at an identity and device platform, it is close to ideal: it shows product judgment (prioritisation under noise), AI-native building (agents, evals, grounding), and executive communication (portfolio view, board memo) in one demo, and the synthetic domain (AI-agent identities, SCIM, device trust, patching) is the interviewer’s own world.

The weak spots are differentiation against existing feedback-intelligence tools and the unglamorous plumbing of matching people across systems. Both are fixable in the pitch.

    Synthetic data schema

    Thirteen tables in four groups: the three pillars, reference data, and tables the agents write. The generator plants twelve themes with known ground truth, so clustering and scoring can be evaluated, not just eyeballed.

    Planted themes (ground truth)

    Each theme is seeded with a pattern the agents must rediscover.

    IDThemePlanted pattern

    Join keys that make triangulation possible

    • account_id on every pillar table: the identity-resolution step guarantees it.
    • feature_key links a theme to the telemetry it should move.
    • module_id rolls themes and FTE up to the portfolio.
    • gt_theme_id is hidden from agents and used only by evals.
    • evidence_citations ties each claim in a brief to source rows.

    Agentic pipeline
    
    
    A LangGraph state machine. Arithmetic and penalties are deterministic SQL; the models do what models are good at: reading, naming, arguing and writing. Dashed steps are code, solid steps call Claude.
    
  
    
  
    
    
    Nightly run
    
    
    
    
    Conditional edge: if the Grounding Judge fails a claim, the brief returns to the Briefing Agent with the failing claim attached (maximum two retries, then the claim is dropped and logged).
    
  
    
  
    
  
    
    
    
      
    Scoring
    
      
    Q = 0.45·log-scaled unique accounts + 0.20·source diversity
  + 0.25·urgency + 0.10·workaround rate
B = max( abandonment lift vs non-complainers × usage coverage,
         usage decline in renewal cohort / 0.45 )
C = log-scaled $ (urgency-weighted ARR + at-risk ARR + blocked pipeline)
  × (0.75 + 0.25·ICP share)

evidence = 100 × (0.30·Q + 0.35·B + 0.35·C) × skeptic_penalty
penalty  ×0.55 if one account holds >60% of the dollars
         ×0.85 if one account holds >35%, if only one source,
               or if <50% of complainers use the feature
